Annotations

Numbers match the black callouts above. This page is a clickable wireframe: mode, contrast, compare, screen tabs, device frames, role filter, role highlight and the inspector all work, so you can try the flow before anything is designed.

1
Top bar

Global controls only. Stays fixed so mode can be flipped while scrolling any screen. Shows which token export version is loaded.

2
Light / Dark

Segmented toggle (not an icon-only button) so the current state is always readable. Keyboard: Tab then arrow keys.

3
Contrast level

Standard / Medium / High. Combined with (2) this selects one of the 6 ANTZ schemes. Default follows the OS (prefers-color-scheme, prefers-contrast).

4
All modes side by side

Replaces the single preview with a 3 × 2 grid of the current screen in all 6 schemes (12). Mode and contrast controls are then disabled.

5
Export

Downloads the same files the ANTZ skill already ships (CSS vars, Tailwind, JSON, Flutter, MUI/shadcn). Export is always all 6 modes, never just the one on screen.

6
Role list

Every M3 role grouped by family. Each row: swatch, token name, hex, the on-colour it pairs with, contrast ratio and AA / AAA badge. Values update with (2) and (3).

7
Filter

Type to narrow roles (e.g. "container", "fixed"). Also a "failing only" filter later, if any pair ever drops below AA.

8
Read-only by design

Unlike Material Theme Builder there is no seed or custom colour. The palette is fixed to ANTZ; the tool is for checking, not choosing.

9
Screen rail

One thumbnail per real sample in Design System Previewer/screen samples (12 iPhone screenshots of the ANTZ mobile app), named after the screen and labelled with its file. In the real app the thumbnails are live mini-renders.

10
Device frame

Defaults to Mobile 375 because every sample is a phone screen. Tablet / Desktop only stretch the same layout until we have web dashboard samples (see open questions).

11
Live preview

Wireframe recreation of the selected sample, painted only with ANTZ role tokens (photos stay as hatched placeholders). Hover outlines what is clickable; click to inspect (13); clicking a role in (6) highlights where it is used.

12
Comparison grid

Same screen, all 6 schemes, at half scale. Footer of each card shows how many key pairs pass AA. Click a card to open it full size in that mode.

13
Inspector

For the clicked element: background, text and border roles, hex in the current mode, a strip of the same role in all 6 modes, contrast of the pair and a copyable CSS snippet.

15
Proposed role mapping

For each region of the sample: which ANTZ role it would use, with live swatches for the current mode. Click a row to highlight that region in the preview. "Today" notes describe the colour in the screenshot. This is the list to approve before the high-fidelity phase.

14
Phase 2: your real app

Iframing our live apps will likely be blocked by X-Frame-Options / CSP and needs logins. Safer options: screenshot colour-mapping, or a bookmarklet / browser extension that injects tokens.css into the real page.

Open questions

  1. Are the proposed role mappings (15) right? Main judgement calls: navy banners and selected chips as tertiary / inverse-surface, module gradient tiles flattened to primary / tertiary containers, peach "Pending" as error-container.
  2. All 12 samples are mobile. Do we also need web dashboard screens (pharmacy, lab, login) for the desktop frame?
  3. Module tiles and photos use gradients and imagery today. Keep the 5 Figma module gradients, or move tiles to flat ANTZ containers?
  4. The speed-dial menus (IMG_1606, IMG_1611) use a white wash; M3 uses a 32% scrim. Which should the tester show? The 11-item Medical menu is also long for a speed dial.
  5. Which token set is the source of truth? The Figma "ANTZ Colour" library of 3 Nov (65 roles, navy tertiary #1F415B, error #E93353, extended Success / Warning / Caution / Info) is newer than the files on disk (49 roles, 27 Oct export). This wireframe shows the on-disk values.
  6. Extended colours are used heavily (Alert for the audit ticker and "in progress", Warning for the "F" badge). Should they become mode-aware roles? On disk they are single fixed hexes, so they do not change between modes in this wireframe.
  7. Do we want the Phase 2 "test my real app" mode, and if so screenshot mapping or a token-injection extension?
  8. Who uses this: designers only, or developers too? That decides whether Export and code snippets are prominent or tucked away.
  9. Hosting: internal static page, or part of the web dashboard behind login?

Legend

  • n numbered callout, explained above
  • AAA pair is 7:1 or more · AA 4.5:1 or more · AA large 3:1 or more (non-text / large text) · Fail below 3:1
  • Grey boxes and bars are placeholder content, not final copy or layout.
  • Pink outline in the preview marks the element being inspected or a highlighted role.
  • Out of scope for v1: state layers, typography, shape and elevation tokens (not yet defined in ANTZ).
